# Restructuring report

This is the historical report of the initial restructuring. For the current
layout, see [project structure](project-structure.vi.md). The inventory below
includes historical paths and placeholder folders that have since been removed.

## Follow-up: persistent local PostgreSQL setup

The original restructuring results below describe the initial move. A later
request configured local startup without `setx` and resolved the earlier runtime
and wrapper issues:

- Updated `backend/src/main/resources/application.yaml` to import the optional
  external file `./config/application-local.properties`, relative to `backend/`.
  Existing datasource placeholders and Hibernate settings were retained.
- Created `backend/config/` and `backend/config/application-local.properties`
  containing this machine's PostgreSQL settings. The credentials file is excluded
  by a new rule in `.gitignore` and is not included in the application JAR.
- Created `backend/config/application-local.properties.example` without real
  credentials for future checkout setup.
- Updated `backend/mvnw.cmd` to handle a missing Maven cache symbolic-link target
  on Windows PowerShell without indexing a null array.
- Updated the root `README.md` with the local setup and launch instructions.
- Updated this report with the follow-up changes and verification results.

Verification after removing `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` from the
test processes: `mvnw.cmd -B test` passed (1 test, 0 failures, 0 errors), and the
exact `mvnw.cmd spring-boot:run` command connected to PostgreSQL and started Tomcat
on port 8080. An HTTP request reached the application and returned the expected
404 for the unimplemented root endpoint. The temporary server was stopped after
verification. No banking business logic was changed.

- JDK 21: production and test sources compiled successfully.
- Cached Maven 3.10.0: `-B -DskipTests package` passed and created the executable
  Spring Boot JAR at `backend/target/banking-0.0.1-SNAPSHOT.jar`.
- The existing `contextLoads` test ran, but PostgreSQL rejected password
  authentication for user `postgres` (SQLSTATE `28P01`). Full database-connected
  startup could not be verified in this shell. No database settings were changed.
  Reuse any environment variables or IDE settings from the previously working launch.

  PowerShell `Cannot index into a null array` at its existing `.Target[0]` lookup.
  Validation used its already cached Maven 3.10.0 distribution directly. The
  wrapper itself was not edited.
- `npm.cmd install` succeeded (72 packages audited; zero reported vulnerabilities).
- `npm.cmd run build` passed TypeScript checking and Vite production bundling.
- `npm.cmd run dev -- --host 127.0.0.1 --port 5173 --strictPort` started Vite.
  HTTP checks returned 200 for `/`, `/src/main.tsx`, and `/src/App.tsx`, including
  the expected application title. The temporary dev server was stopped afterward.
- No transfer, authentication, Redis, Kafka, or fraud behavior was implemented.
  `docker-compose.yml` contains only an empty services mapping.
